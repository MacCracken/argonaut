# Contributing to Argonaut

Thank you for your interest in contributing to Argonaut.

## Development Workflow

1. Fork and clone the repository.
2. Create a feature branch from `main`.
3. Make your change, with a `.tcyr` regression test for any behaviour change.
4. Run the gates below; CI blocks on each of them.
5. Open a pull request, with a CHANGELOG entry.

## Prerequisites

- The [Cyrius](https://github.com/MacCracken/cyrius) toolchain at the version pinned in
  `cyrius.cyml` (`[package] cyrius`). That field is the only pin; there is no
  `.cyrius-toolchain`.
- Linux x86_64. aarch64 is cross-built and tested under `qemu-aarch64`
  (`scripts/aarch64-sweep.sh`).

## Gates

| Command | What CI checks |
|---------|----------------|
| `cyrius deps --verify` | `cyrius.lock` hashes match |
| `cyrius lint src/*.cyr` | no lint warnings (blocking) |
| `cyrius fmt <file> --check` | no format drift, for each `src/*.cyr`, `tests/tcyr/*.tcyr` and `tests/bcyr/*.bcyr` (blocking) |
| `cyrius vet src/main.cyr` | include dependencies |
| `CYRIUS_DCE=1 cyrius build --check-lib-sync src/main.cyr build/argonaut` | the release build |
| `for t in tests/tcyr/*.tcyr; do cyrius test "$t"; done` | every suite, 0 failures |
| `cyrius bench tests/bcyr/argonaut.bcyr` | benchmarks (non-fatal in CI) |

A release also runs the benchmark gate, `./scripts/bench-history.sh "<version>-<label>"`,
against the prior label (see CLAUDE.md).

## Project Structure

```
src/           application modules (.cyr)
tests/tcyr/    test suites (.tcyr)
tests/bcyr/    benchmarks (.bcyr)
tests/         test_header.cyr: shared includes and helpers
qemu/          the PID-1 boot harness (KVM)
scripts/       bench history, aarch64 sweep, Pi smoke test
docs/          architecture notes, ADRs, guides, audits, roadmap, state
lib/           generated by `cyrius deps` from cyrius.cyml (gitignored)
```

## Adding a Module

1. Create `src/module_name.cyr`.
2. Add its `include` to `src/main.cyr` **and** to `tests/test_header.cyr`, at the same
   position in both lists (dependencies first).
3. A new stdlib module goes in `cyrius.cyml` `[deps] stdlib`, never as an `include` in a
   source file.
4. Add tests in `tests/tcyr/module_name.tcyr`.
5. Update CHANGELOG.md.

## Cyrius Conventions

The full list is in CLAUDE.md; the ones that bite most often:

- Everything is i64. Struct fields are 8 bytes and are accessed with `load64` /
  `store64` or the generated accessors; allocate with `sizeof(StructName)`.
- Long-lived data uses `alloc()` (bump arena, never freed). Data with its own lifetime
  uses `fl_alloc()` / `fl_free()`.
- Strings are `Str` values (`str_from`, `str_data`, `str_len`). A Str's bytes are **not**
  NUL-terminated at its length, so compare with `str_eq` / `str_eq_cstr`, not `streq`.
- Errors: `Result` (`Ok` / `Err`), or a documented sentinel such as `-1` or `0`. Check
  every return.
- Reserved words: `match`, `trait`, `const`, `true`, `false`, `do`, `dyn`.
- No `break` in a `while` loop that declares a `var`; use a flag and `continue`.
- Don't mix `&&` and `||` in one expression; nest `if` blocks.
- Always `return 0;`, never a bare `return;`.
- A function-local `var buf[N]` is N bytes of **static** storage, not stack.

## Code Style

- One module per `.cyr` file, with a comment block at the top.
- Function names: `prefix_verb_noun()` (e.g. `init_start_service()`,
  `audit_log_record()`).
- Constants via `enum` blocks.
- SafeCommand for all process execution (no shell strings).
- Per-arch syscall numbers go in `src/syscall_compat.cyr`, and only where the stdlib has
  no `sys_*` wrapper.
