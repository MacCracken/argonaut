# 2026-08-24 — 1.8.6 P(-1) audit

Fourth P(-1) pass, and the first since 2026-05-11 (1.6.3). Covers the
surface as of 1.8.5: cyrius **6.5.35**, libro **2.8.12** (patra 1.13.10 /
sigil 3.12.9 / sakshi 2.4.11, all stdlib-folded). Baseline is the
`1.8.6-audit-baseline` row in `bench-history.csv`; 28 `.tcyr` suites / 748
assertions green going in.

Severity tags per project convention: **CRITICAL** (remote / priv-esc),
**HIGH** (moderate effort), **MEDIUM** (specific conditions), **LOW**
(defense-in-depth), **UPSTREAM**.

## How to read this report

Every finding below was put through an **adversarial verification pass**
whose explicit job was to refute it. Six findings were originally filed at
HIGH; four were refuted outright and the two survivors were corrected
**down to MEDIUM**. **Nothing in this report is HIGH.** That is the honest
result of a codebase on its fourth pass, and the delta between "what the
sweep claimed" and "what survived" is recorded in *Considered and
dismissed* rather than quietly dropped.

Separately, and per the CLAUDE.md rule that every MEDIUM+ earns a failing
regression test *before* its fix, each closed finding below carries a test
that was **observed failing against the unfixed tree**. Where that test
produced a measurement, the measurement is quoted. That is a stronger
claim than "an auditor asserted it", and the *Evidence* line on each
finding says which kind of confirmation it has.

## Structural framing (bounds every severity below)

Three facts constrain every claim in this report. All three were verified
by reading and grepping `src/`, not inferred.

1. **The shipped PID-1 loop does very little.** `src/main.cyr` mounts
   `/proc`, `/sys`, `/dev`, optionally runs the harness, blocks
   SIGTERM/SIGINT/SIGCHLD onto a signalfd, then loops on
   `init_reap_services()` + signalfd drain until poweroff. It **never**
   calls `init_start_service`, `init_poll_health`, `init_enforce_watchdog`,
   `init_notify_bind`, or `init_stop_service` — verified: zero callers of
   any of them outside `src/init.cyr` itself. The service-lifecycle
   machinery is **library surface consumed by kybernet, not reachable from
   the shipped `/sbin/init`**. That is a genuine mitigation today and a
   genuine liability the day the loop is wired; findings that depend on it
   say so.
2. **There is no configuration parser.** No `toml_get` / `json_get` /
   unit-file parse anywhere in `src/*.cyr`, and no string→enum health-type
   parser (only enum→string). No config file, CLI argument, or network
   input reaches a service definition — everything is a source literal or
   a consumer-supplied struct. This is why much of what follows is
   *developer-API misuse* rather than *attacker-controlled input*, and why
   the severities are what they are.
3. **seccomp / Landlock / capabilities are NOT enforced.**
   `src/security.cyr` contains **zero syscalls**: `seccomp_description` and
   `landlock_description` build human-readable strings, and
   `capability_setpriv_cmd` builds a `setpriv` command that nothing
   executes. `svc_def_new` stores `0` for all three fields, and nothing in
   the spawn path reads them. Every service `fork_exec_service` starts
   inherits PID 1's full root privileges. See **DOC-1**.

## [MEDIUM-1] `notify_parse` hashes a non-NUL-terminated key past the receive buffer

- **File:** `src/notify.cyr` — `notify_msg_new` (`map_new()`) and
  `notify_parse` (`map_set(fields, str_data(key), val)`).
- **Behaviour:** `map_new()` builds a **cstr-keyed** map, so `_map_hash`
  uses `hash_str`, which walks `while (load8(s + hi) != 0)`. The key handed
  to it is `str_data(key)` — a raw pointer into the shared module-level
  receive buffer, which `sys_read` leaves with **no NUL terminator**. The
  hash therefore walks past the intended key, through the rest of the
  datagram, and off the end of the allocation until it happens to find a
  zero byte.
- **Evidence (measured on the unfixed tree):** parsing the 22-byte
  datagram `READY=1\nSTATUS=running` in a 64-byte buffer whose tail was
  filled with non-NUL bytes gave a stored key whose `strlen` was **65** —
  one byte past a 64-byte allocation — and `map_get(fields, "READY")`
  returned **0**, i.e. the `fields` map was entirely non-functional.
- **Impact:** an unbounded read driven entirely by attacker-controlled
  datagram content. The production buffer is `alloc(1024)` and `sys_read`
  can fill all 1024 bytes with no NUL, so the walk runs into the bump arena
  until it finds a zero. Bump memory is mapped, so this is normally an
  over-read rather than a fault — but a buffer landing near the end of an
  arena chunk faults, and a SIGSEGV in PID 1 is a kernel panic. Secondary:
  the `fields` map has never worked (no in-tree consumer reads it, which is
  why this went unnoticed).
- **Reachability:** production reaches `notify_parse` through
  `notify_try_recv_authenticated` (`src/init.cyr:707`), which requires
  SCM_CREDENTIALS and PID membership — so the sender must be a service
  argonaut spawned. The unauthenticated `notify_drain` path reaches it from
  any local process.
- **Fix:** `map_new_str()` (length-based hashing, no NUL walk) plus
  `str_clone` on both key and value so each message owns its bytes. The
  clone also closes a second latent bug: `str_new` **borrows** the shared
  buffer, so `notify_drain` returned N messages whose strings all aliased
  the last datagram.
- **Test:** `audit-2026-08-24-medium1-notify-fields-key` — asserts the map
  resolves its own keys, that the first key is 5 bytes (`READY`) rather
  than the whole datagram, and that a parsed value survives the caller
  overwriting the buffer.

## [MEDIUM-2] `execute_health_check` returns a bare `0` for a non-`http://` target

- **File:** `src/health.cyr`, `HC_HTTP_GET` branch.
- **Behaviour:** the scheme check short-circuited with `return 0` — the
  only exit from `execute_health_check` that is not a heap
  `HealthCheckResult`. The sibling rejection paths added by the 1.5.5 audit
  (port range, invalid host byte, resolver miss) all correctly return a
  struct.
- **Callers, all unguarded:** `src/health.cyr:468`
  (`if (load64(result + 16))`), `src/init.cyr:676`
  (`var hc_passed = load64(result + 16);`).
- **Evidence:** the regression test **crashed the test binary outright**
  against the unfixed tree — no summary line printed.
- **Impact:** `load64(0 + 16)` reads `0x10`, below `mmap_min_addr`. In the
  PID-1 health loop that is a whole-machine panic with no audit record.
- **Why MEDIUM, not HIGH:** reachability is developer-API misuse only. Per
  the structural framing, no config parser exists, and every in-tree
  `HC_HTTP_GET` target is an `http://` literal. The trigger is a consumer
  hard-coding `https://` (a natural choice for a TLS endpoint) or a bare
  `host:port`. It fails deterministically on the first health tick.
- **Fix:** return a failed `HealthCheckResult` with an explicit
  "unsupported scheme" message.
- **Test:** `audit-2026-08-24-high1-health-null-result` — covers
  `https://`, uppercase `HTTP://`, bare `host:port`, empty string, and
  malformed `http:/`.

## [MEDIUM-3] The PID-1 supervisor loop leaks bump arena on every tick

- **File:** `src/main.cyr` loop → `init_reap_services` (`src/init.cyr`) →
  `proc_table_reap` (`src/process_mgmt.cyr`).
- **Behaviour:** the loop calls `init_reap_services()` every 100 ms,
  forever, and discards the result. Each call allocated unconditionally
  from the **bump** allocator — `map_keys()` inside `proc_table_reap`, plus
  two `vec_new()`s — and bump memory is never individually freed.
- **Evidence (measured on the unfixed tree):** **456 bytes per idle tick**
  = ~**375 MB/day**, ~11 GB/month. The regression test measured **228,000
  bytes over 500 idle ticks**.
- **Impact:** PID 1 cannot be restarted. The arena grows monotonically
  until allocation fails, and init dying is a kernel panic. This is a
  timer, not a trigger — no attacker needed.
- **Fix:** iterate the proc table **in place** via `map_entries`/`map_cap`
  (stride 24: key, value, occupied) instead of materialising a key vec, and
  allocate the `exited` / `results` vecs **lazily**, only once something has
  actually exited. A shared never-mutated empty vec is returned otherwise,
  so the public contract is unchanged.
- **Test:** `audit-2026-08-24-high2-pid1-idle-arena-growth` — asserts 500
  idle reap ticks allocate **exactly zero** bytes. Asserting zero rather
  than a threshold is deliberate: any per-tick allocation at all is
  unbounded over the life of PID 1.
- **Post-fix:** measured 0 bytes/tick.

## [MEDIUM-4] Merkle proof verification was self-referential (BREAKING API)

- **File:** `src/audit_ext.cyr` — `audit_log_verify_inclusion(proof)` and
  `audit_log_verify_consistency(cp)`.
- **Behaviour:** both delegated to libro primitives that check a proof
  against the root carried **inside that same proof**. libro documents this
  itself: *"an append-only proof that proves nothing about YOUR log is
  worse than no proof, because pv_is_valid reports it as passing."* The
  1-arg signatures made the correct check structurally impossible — a
  caller holding an entry and a proof had no way to tie the two together.
- **Impact:** a proof built over an entirely fabricated chain verifies. For
  a tamper-evident audit chain that is the whole mechanism. Consumers
  (kybernet, stiva, sutra, daimon) verifying an inclusion proof learned
  only "this proof is internally consistent", never "this entry is in the
  log I trust".
- **Fix — breaking, deliberately:** `audit_log_verify_inclusion(proof,
  expected_root, entry_h)` via `merkle_verify_inclusion`, and
  `audit_log_verify_consistency(cp, expected_new_root)` via
  `merkle_verify_consistency_against`. Both bindings now come from the
  caller. **Migration is safe by construction:** cyrius 6.5.1 made a
  wrong-arity call a hard compile error, so every stale call site fails
  loudly at build time rather than silently keeping the old semantics.
- **Test:** `audit-2026-08-24-medium2-merkle-proof-binding` — builds two
  chains and asserts a proof from chain A verifies against A's root,
  is **rejected** against B's root, and is **rejected** for an entry it does
  not cover.

## [MEDIUM-5] `verify_emergency_auth` fails **open** when no hash is configured

- **File:** `src/security.cyr`.
- **Behaviour:** `if (stored_hash == 0) { return 1; }` — with
  `require_auth` set but `auth_password_hash` unset, the function
  **granted** access.
- **Impact:** a misconfiguration hands out an unauthenticated emergency
  root shell. `require_auth` is the operator's explicit intent; a missing
  credential means the check cannot be satisfied, not that it should be
  skipped.
- **Fix:** return 0 (deny). The correct-password and auth-not-required
  paths are unchanged.
- **Test:** `audit-2026-08-24-medium3-emergency-auth-fail-closed`.
- **Not fixed, filed as follow-up:** `password_hash` is a bare unsalted
  single-round SHA-256. Adequate against a shoulder-surfer, weak against an
  offline attacker with the stored hash. A real KDF needs a dependency that
  the thin sigil surface does not carry — deferred, see *Deferred*.

## [MEDIUM-6] tmpfiles device-type argument aliases one static buffer

- **File:** `src/tmpfiles.cyr`, `generate_tmpfile_commands`.
- **Behaviour:** the mknod type argument was built from a function-local
  `var type_buf[2]` and handed out via `str_from(&type_buf)`. A fixed-size
  local in Cyrius is **static storage, not stack**, and `str_from`
  **borrows** the pointer — so every device entry in one call returned a
  Str aliasing the same two bytes.
- **Evidence:** the regression test failed on all three assertions against
  the unfixed tree, including the block device's own type.
- **Impact:** a config creating a **character** device followed by a
  **block** device emitted `mknod <path> b …` for both — argonaut creates
  the character device with the wrong node type at boot.
- **Fix:** build a fresh Str per entry via `str_builder_putc`.
- **Test:** `audit-2026-08-24-medium4-tmpfiles-devtype-aliasing`.

## [MEDIUM-7] `execute_health_check` dereferences `target` with no null check

- **File:** `src/health.cyr`.
- **Behaviour:** every check type except `HC_PROCESS_ALIVE` dereferences
  `target` — `resolve_host_ipv4(target)` for TCP, `check_command(target,…)`
  for COMMAND, `str_data(target)` for HTTP. `HC_PROCESS_ALIVE` legitimately
  has no target, so copying that idiom and changing the type yields
  `target = 0`.
- **Evidence:** the regression test **crashed the test binary** against the
  unfixed tree.
- **Impact:** reads address `0x8`; in the PID-1 health loop, a kernel panic.
  Same class and same reachability argument as MEDIUM-2.
- **Fix:** one guard covering all target-requiring types, returning a
  failed result with "no target configured". `HC_PROCESS_ALIVE` still works
  with a null target.
- **Test:** `audit-2026-08-24-medium5-health-null-target`.

## [MEDIUM-8] systemd unit injection via dependency name; unit-filename traversal

- **File:** `src/systemd.cyr` — `generate_unit` and
  `generate_unit_filename`.
- **Behaviour:** `Description=` was sanitised through
  `sanitize_unit_value`, but dependency names were added to `After=` /
  `Requires=` **raw**, and `generate_unit_filename` interpolated the
  service name **raw**.
- **Impact:** a dependency name carrying a newline closed the `After=` line
  and opened its own section, injecting arbitrary directives — e.g. a
  second `ExecStart=` — into a unit file systemd then runs as root. A
  service name containing `/` or `..` escaped the unit directory the caller
  writes into. argonaut is a unit **generator**, so this is the trust
  boundary that matters if definitions ever come from a package or a less
  trusted source.
- **Fix:** route dependency names through `sanitize_unit_value` (newline →
  space, so the payload survives as inert text on the `After=` line and can
  never begin a directive), and add `sanitize_unit_name`, which reduces a
  service name to `[A-Za-z0-9_.-]` with a non-leading `.` so the result is
  always a single path component that can be neither `.` nor `..`.
  Well-formed names are unchanged.
- **Test:** `audit-2026-08-24-medium7-systemd-unit-injection`.
- **Cost:** `generate_unit` +0.506 µs (+10.4 %) — see *Benchmarks*.

## [MEDIUM-9] Forking-service PID file adopted without the ownership check

- **File:** `src/process_mgmt.cyr` `read_pid_file`, called from
  `src/init.cyr` when adopting a forking service's daemon PID.
- **Behaviour:** `read_pid_file_safe` already implements the ownership and
  group/other-writability checks — they were added for the M4
  (CVE-2025-4598 class) work — but the wrapper the one production call site
  uses passed `-1`, the sentinel that **skips** the ownership check. The
  mitigation existed and was simply not connected.
- **Impact:** **CVE-2018-16888 class.** A service whose PID file sits in an
  attacker-writable location can hand argonaut an arbitrary PID to adopt,
  track, and later signal. systemd's fix for the identical bug is to trust
  a PID file only when it is root-owned.
- **Fix:** `read_pid_file` now passes `sys_getuid()` — "owned by the uid
  argonaut itself runs as", which is uid 0 under PID 1 and generalises
  correctly for a test sweep. An explicit uid can still be passed to
  `read_pid_file_safe` for a service known to drop privileges; `-1` remains
  available for a caller that genuinely needs the legacy behaviour.
- **Test:** `audit-2026-08-24-medium6-forking-pidfile-owner`.

## LOW findings (all closed)

- **[LOW-1] `/etc/hosts` silently truncated at 8 KB.** `file_read_all`
  fills the buffer and returns the count with **no truncation signal**, so
  a caller passing 8192 cannot distinguish "exactly 8192 bytes" from "more,
  clipped". Entries past the cap became unresolvable, and a health check
  against such a host reports the service DOWN — under PID 1 that restarts
  a service that was fine. The module's own comment anticipates large
  fleet-pinned hosts files. **Fixed:** read one byte past the cap to make
  the overflow detectable, warn via sakshi, and clip the scan back to the
  last complete line so a record severed mid-token is never parsed.
- **[LOW-2] `backoff_delay` integer overflow.** `shift` saturates at 1e9,
  so an unvalidated `base_delay_ms` above ~9.2e9 overflowed i64 in
  `base * shift` and produced a **negative** delay, which then sailed past
  the `delay > cap` clamp. **Fixed:** clamp `base` to `cap` before
  multiplying, plus a negative-result backstop.
- **[LOW-3] HTTP request write unchecked; status line single-read.** A
  short or failed `write()` fell through to the poll and surfaced as "HTTP
  response timeout", blaming the peer for a local error. Separately, a
  single `read()` assumed the whole status line arrived in one segment — a
  server splitting `HTTP/1.1 200 OK` across TCP segments was reported as an
  "invalid HTTP response", a **false negative that restarts a healthy
  service**. **Fixed:** check the write; loop the read until a line
  terminator, the peer closes, or the poll budget is spent.
- **[LOW-4] `FleetRegistration.kernel_ver` aliases the shared read buffer.**
  `fleet_registration_from_system` clones the machine-id and hostname reads
  but not the `/proc/version` one, so the returned struct's
  `kernel_version` pointed into a `var buf[256]` that the next call
  rewrites. The in-source comment claimed "buf is on stack" — it is
  **static**. **Fixed:** clone, and correct the comment.
- **[LOW-5] `SO_ERROR` read uninitialised.** `var so_err[8]` was never
  zeroed and `getsockopt`'s return was ignored. `so_err` is static storage,
  so a failed `getsockopt` left the previous call's value in place — and a
  stale `0` reports a **refused** connection as a successful one, precisely
  the "misleading green badge" this module exists to prevent. **Fixed:**
  zero the buffer, check the return, fail closed.
- **[LOW-6] `signalfd` return unchecked.** SIGTERM/SIGINT/SIGCHLD are
  blocked immediately before, so a failed `signalfd` left the loop spinning
  on fd −1 with the shutdown signals masked — an **unkillable PID 1 that
  never powers off**. **Fixed:** check it, unblock the signals, and fail
  loudly rather than silently becoming unresponsive.

## [DOC-1] Documentation claimed security enforcement that does not exist

`docs/architecture/feature-gaps.md` recorded seccomp/Landlock/capabilities
as **"Implemented (v0.9.0) … + agnosys integration"**. Two things are wrong
with that: `src/security.cyr` contains **zero syscalls** and nothing in the
spawn path reads the `seccomp` / `landlock` fields, and **agnosys was
dropped from the dependency graph at 1.8.4**. An operator reading the docs
would believe services are confined when they run with PID 1's full root
privileges.

This is not a code defect — the code never claimed to enforce anything —
but a documented mitigation that does not exist is worse than an absent
one. **Corrected** in `feature-gaps.md` and in CLAUDE.md's project
description; real enforcement is filed as roadmap work, not a patch-release
fix.

## Considered and dismissed

Recorded so they are not re-filed next pass. Four findings were filed at
HIGH by the sweep and **refuted** on verification:

- **`exec-bare-binary-relative-path`** (claimed HIGH: PATH-hijack via bare
  binary names in `run_safe_cmd`) — refuted. The claimed root-exec
  primitive does not hold from any real entry point, and it re-files a
  known LOW.
- **`fork-exec-fd-leak-no-cloexec`** (claimed HIGH) — the mechanical
  observation is accurate but the security impact is essentially null and
  it re-files a known LOW.
- **`pid1-shutdown-skips-orchestration`** (claimed HIGH) — refuted outright
  after reading `main.cyr`, `init.cyr`, the roadmap and CHANGELOG; the
  behaviour is the documented design of the current supervisor loop.
- **`pid1-exits-if-reboot-returns`** (claimed LOW) — the memory-safety
  mechanism is real but unreachable from any runtime entry point.

Also examined and **not** filed:

- **`audit_log_open_persistent` I/O-failure fallback.** The theory was that
  `patrastore_load_all` folding a failed query into an empty vec would let
  argonaut start a fresh chain and skip the replay tamper check. **Probed
  directly and could not reproduce:** `chmod 000` fails at
  `patrastore_open`; half-file, header-only and zero-length truncation are
  all caught by `patrastore_open` or by the existing `chain_verify`. Filed
  as **defense-in-depth only** and fixed anyway (`patrastore_load_all_or_err`
  + `libro_is_error`, failing closed) because the fix is one line and
  removes the reliance on those two paths continuing to cover it. **No
  concrete bypass was demonstrated and none is claimed.**
- **`str_data` passed to `execve`.** Checked: `str_from`,
  `str_builder_build` and `str_clone` all produce NUL-terminated buffers,
  so argv/envp construction in `fork_exec_service` is sound. Only bare
  `str_new(ptr, len)` borrows without terminating, and no such Str reaches
  execve.
- **`break` inside `for` loops declaring a `var`.** CLAUDE.md warns about
  this for `while`; the `for` instances in `process_mgmt.cyr` and
  `health.cyr` behave correctly under 6.5.35 and are left alone.

   PID must be in the unit's cgroup". argonaut has no equivalent invariant.
   MEDIUM-9 closes the immediate PID-file hole; the PID-reuse window
   between reading a PID file and signalling it remains open by design.
   Filed as roadmap work.
2. **No privilege separation at all** (DOC-1). Every service runs as root
   with all capabilities. This is the single largest gap between argonaut's
   stated surface and its behaviour.

## Benchmarks

**Zero regressions** across all 29 micros, both post-audit vs the step-3
baseline and at the release gate (`1.8.6-p-minus-1-audit` vs
`1.8.5-cyrius-6.5.35`).

**One claim was made and then withdrawn, and the withdrawal is the useful
part.** The `1.8.6-post-audit` run showed `generate_unit` +0.506 µs
(+10.4 %), and it was first written up as the attributable cost of
MEDIUM-8's dependency-name sanitization — a plausible story, since that fix
does add a per-character loop. Re-running the **same binary** under the
release label gave 4.835 µs. Across four labels the micro reads 4.911 /
4.860 / 4.835 / 5.366, and the outlier run carries the **lowest `min` of
all four** (3.873 µs) against a 16.5 µs `max`. That is scheduling noise in
the mean, not the sanitizer. The cost of the fix is **not measurable at
this resolution**, and the earlier attribution was wrong.

MEDIUM-3's fix is the one unambiguous win, and it is not a micro at all —
the PID-1 idle tick went from 456 bytes/tick to **0**, and
`proc_table_reap` no longer materialises a key vec per call.

## Follow-ups filed (not fixed in 1.8.6)

- **Real seccomp / Landlock / capability enforcement** (DOC-1). A feature,
  not a patch.
- **cgroup or pidfd-based PID identity** to close the PID-reuse window that
  MEDIUM-9 only narrows.
- **A real KDF for the emergency-shell password** (MEDIUM-5) — needs a
  dependency the thin sigil surface does not carry.
- **The unauthenticated `notify_drain` / `notify_try_recv` path.** It
  bypasses the M1 SO_PEERCRED check entirely. No production caller today
  (`src/init.cyr` uses the authenticated variant), so it is a footgun
  rather than a live hole — but it should either be removed or renamed to
  make the distinction impossible to miss.
- **Wiring the supervisor loop** to the lifecycle machinery. Several
  severities in this report are bounded by the fact that it is not wired;
  they must be re-rated the day it is. **That is a re-audit trigger.**
