# 2026-10-14 — 1.16.1 hardening and optimization pass

> **Updated at 1.16.2.** Every item this pass deferred is now closed. Two more LOWs, found
> while closing them, are fixed too. See [Fixed at 1.16.2](#fixed-at-1162-previously-deferred).

The fifth audit pass, and the first since 2026-08-24 (1.8.6). It covers the surface as of
1.16.0: cyrius **6.7.9**, libro **2.11.0** (sigil 3.13.12, patra 1.16.0, sakshi 2.5.8).
Going in, 34 `.tcyr` suites and 1,017 assertions were green, and the bench baseline is the
`1.16.0-cyrius-6.7.9` row in `bench-history.csv`.

Severity tags follow project convention: **CRITICAL** (remote / priv-esc), **HIGH**
(moderate effort), **MEDIUM** (specific conditions), **LOW** (defense-in-depth), **PERF**.

## How this pass was run

1. **Four read-only reviews ran in parallel**, each told to refute its own candidates before
   reporting them:
   - network and IPC input (`health`, `resolver`, `notify`);
   - process, exec and filesystem (`process_mgmt`, `tmpfiles`, `systemd`, `edge_boot`,
     `security`);
   - core lifecycle, the PID-1 loop and audit (`init`, `main`, `types`, `services`, `audit*`,
     `pid1_harness`, `boot`), plus performance;
   - a known-CVE sweep of 2025–2026 init, service-manager and systemd advisories.

   Most findings came with a probe that reproduced them in a scratch copy of the tree.
2. **Every MEDIUM got a regression test that failed against the unfixed tree before the fix
   went in**, per CLAUDE.md. Most LOWs got one too. The fixes were made in three lanes that
   shared no source file (network, process, core), and the PID-1 loop and resolver were done
   separately. Each lane ran the full gates in its own copy. Each patch was then reviewed and
   applied, and the full gates ran again on the combined tree.
3. **Where a test produced a number, the number is quoted below.** Each finding's
   *Evidence* line says whether a failing test confirms it or only reasoning does.

## Structural framing

The 2026-08-24 framing still holds, with one sharpening:

1. **The shipped `/sbin/init` loop calls none of the service-lifecycle machinery.** It
   mounts, blocks signals onto a signalfd, and reaps. Only C-9 and P-3 below touch it.
2. **kybernet does call that machinery, from its PID-1 reactor, every tick, driven by its
   JSON config.** That config builds health checks, forking services with `pid_file`,
   environment, command checks and privilege drops. So several findings the 2026-08-24 audit
   would have filed as library-only are reachable through kybernet's config. Each finding
   below says which of three reachabilities applies:
   - **shipped binary**;
   - **kybernet** (config-driven, in PID 1);
   - **library-only** (no in-tree or kybernet caller).
3. **seccomp, Landlock and capabilities are still modelled, not enforced.** This is known
   and tracked on the roadmap, and is not re-filed.

## MEDIUM (all fixed)

**A-1: the HTTP health check is bounded per check, not per read.** `src/health.cyr`.
- **Reachability:** kybernet.
- **Defect:** every poll in the status-line read loop got the full timeout. A peer that
  sends one byte every (timeout − ε) ms and never sends `\n` held the check for about
  512 × timeout.
- **Measured:** 2,252 ms for a 200 ms check, which was then reported **passed**.
- **Effect:** in kybernet the caller is PID 1's reactor, so nothing is reaped, no SIGTERM
  is handled and no watchdog runs meanwhile.
- **Fix:** one deadline per check. The connect and every poll get only the time that is
  left, and an unfinished status line is a failure ("HTTP response timeout").
- **Evidence:** 4 assertions in `harden_net.tcyr` failed before the fix. Against a local
  peer that drips one byte every 150 ms, a 300 ms check now returns in under 1 s.

**A-2: a timed-out command leaves its descendants running.**
`src/process_mgmt.cyr`, `run_safe_cmd_timeout`.
- **Reachability:** kybernet (command health checks) and edge boot.
- **Defect:** on timeout, SIGKILL reached only the direct child. A hung grandchild (curl,
  psql) survived every probe, and they piled up under PID 1.
- **Reviewers disagreed:** one dismissed this because "the orphan sweep reaps them". The
  sweep only collects processes that have *exited*. The other reviewer's probe left three
  live `sleep` processes after three timeouts.
- **Fix:** the child leads its own process group (`ag_sys_setpgid`, new in
  `src/syscall_compat.cyr`, verified with `qemu -strace` on both architectures). A timeout
  kills the whole group.
- **Evidence:** "the timed-out command's grandchild is killed with it" failed before the
  fix.

**A-3: the `/etc/hosts` lookup allocates on every probe.** `src/resolver.cyr`.
- **Reachability:** kybernet (any TCP or HTTP check whose target is a hostname).
- **Defect:** a `str_new` per IP token and per name token on every lookup.
- **Measured:** 32–48 B per call on a stock hosts file, and 9,600 B per call on a 200-line
  one. PID 1 never resets its arena, so this grows forever.
- **Fix:** `hosts_scan` / `parse_ipv4_span` compare byte spans with no allocation.
- **Evidence:**
  - 3 assertions failed before the fix, including "a 200-line scan allocates 0 bytes" (got
    384,000).
  - A differential run of the old and new scanner over 1,990 names found no mismatch.

**B-1: the PID-file reader follows symlinks and blocks on FIFOs.** `read_pid_file_safe`.
- **Reachability:** kybernet (forking services).
- **Defect:**
  - A plain `open(O_RDONLY)` meant the owner/mode check `fstat`'d a symlink's *target*. A
    link to another daemon's root-owned 0644 pid file passed MEDIUM-9's check, and argonaut
    later SIGKILLed that daemon. This is the CVE-2018-16888 class, and the CVE sweep
    reached it independently.
  - A FIFO at the path blocked PID 1 in `open` forever.
  - `str_to_int` joined every digit it found ("12 junk 34" became 1234) and had no pid_t
    bound, so "4294967295" became `kill(-1)`.
- **Fix:** open with `O_NOFOLLOW|O_NONBLOCK|O_NOCTTY|O_CLOEXEC`, using the stdlib's
  per-architecture values (`O_NOFOLLOW` differs on aarch64). Require a regular file, and
  parse strictly: digits, one optional newline, 2..2147483647.
- **Evidence:** 8 assertions failed before the fix; the FIFO probe child hung and was
  killed at 2 s. The symlink refusal passes under qemu-aarch64, which checks the per-arch
  flag.

**B-2: unit-file injection survived 2026-08-24 MEDIUM-7.** `src/systemd.cyr`.
- **Reachability:** library-only.
- **Probe-confirmed shapes:**
  - An Environment *key* containing a newline injected `ExecStartPre=/bin/evil`.
  - A value of `v" "LD_PRELOAD=/tmp/e.so` added an assignment.
  - A dependency of `db debug-shell` became `Requires=db debug-shell.service`.
- **By reading:** `%` specifiers expanded, and a lone `;` argument acts as a command
  separator in a oneshot unit.
- **Fix:**
  - Invalid keys are dropped.
  - `"` and `\` are escaped inside the quoted value.
  - Dependency names go through the same sanitiser as unit filenames.
  - `%` is doubled everywhere and `$` only on Exec lines.
  - An empty argument is written `""` and a lone `;` is written `\;`.
  - LOW, same file: `SVC_SIMPLE` rendered `Type=notify`.
- **Evidence:** most of the 19 assertions in `harden_proc.tcyr`'s B-2 group failed before
  the fix, among them "an env KEY cannot inject ExecStartPre=" and "SVC_SIMPLE -> Type=simple".

**B-3: tmpfiles modes are written in decimal but read as octal.** `src/tmpfiles.cyr`.
- **Reachability:** library-only.
- **Defect:** the field is an octal mode (the validator bounds it at 0o7777), but it was
  formatted with `str_builder_add_int`.
- **Probe-confirmed:** 0o660 rendered `chmod 432`, other-writable on a device node; 0o755
  rendered `mkdir -m 493`, which is invalid.
- **Fix:** `tmpfile_mode_octal`. The existing tests stored decimal `755`, which contradicted
  the validator, and now store 493.
- **Evidence:** 3 assertions failed before the fix.

**B-5: edge boot mounts world-writable tmpfs.** `src/edge_boot.cyr`.
- **Reachability:** library-only.
- **Defect:** no `mode=`, so `/var/run` and `/var/log` were 1777; a probe in a user
  namespace showed `drwxrwxrwt`. Any local user could squat a root daemon's pid file or
  socket. No mount set `nodev`.
- **Fix:** `mode=0755` on `/var/run` and `/var/log`, an explicit `mode=1777` on the tmp
  directories, and `nodev,nosuid` on all four.
- **Evidence:** 8 assertions failed before the fix (`nodev` and an explicit `mode=`, on each
  of the four mounts).

**C-1: a STARTING service cannot be stopped, and restarting it starts a second copy.**
`src/init.cyr`, `src/types.cyr`.
- **Reachability:** kybernet and the library.
- **Defect:** STARTING→STOPPING was not a valid transition, so `init_stop_service` refused.
  `init_restart_service` ignored the refusal and forked again, and `init_start_service` on a
  STARTING service forked yet again. All three instances ran at once.
- **Fix:**
  - The transition is allowed.
  - A start is refused unless the service is STOPPED or FAILED.
  - A restart aborts if its stop is refused.
- **Evidence:** 8 assertions in `harden_core.tcyr` failed before the fix.

**C-2: the restart limit was a lifetime budget.**
- **Reachability:** kybernet.
- **Defect:** `restart_count` was only ever incremented. The 5th restart of a
  RESTART_ALWAYS service, even months after the 4th, gave up until reboot.
- **Fix:** `RESTART_STABLE_MS = 10000`, mirroring systemd's `StartLimitIntervalSec`
  default. When a run of at least 10 s ends (reap, stop, watchdog kill or orphan clear), the
  count resets.
- **Deliberately not measured at the restart of an already-dead service.** That would count
  kybernet's backoff wait as uptime, and a crash loop would never give up. A test pins that
  it still does.
- **Evidence:** 6 assertions failed before the fix.

**C-3: watchdog and health deadlines ran on CLOCK_REALTIME.**
- **Reachability:** kybernet.
- **Defect:** an NTP step forward (an edge board's first sync, with no RTC) SIGKILLed every
  watchdog- or health-checked service on the next tick. A step backward silenced the
  watchdog.
- **Fix:** every timestamp that is differenced is monotonic: `started_at`, `last_hc`,
  `last_notify`, and boot start/complete. Boot-step timestamps stay wall-clock because
  `init_boot_log` exports them as dates.
- **P-4, same change:** the watchdog and health loops read the clock once per tick.
- **Evidence:** 7 assertions failed before the fix.

**C-4: oneshot and forking starts blocked in `waitpid(pid, 0)`.**
- **Reachability:** kybernet (`agnos-init` is a desktop oneshot).
- **Defect:** a hung oneshot wedged PID 1's reactor.
- **Fix:** a WNOHANG poll bounded by a start timeout. The default is 90 s (systemd's
  `DefaultTimeoutStartSec`), settable with `argonaut_set_start_timeout_ms`. On expiry the
  process group is SIGKILLed and reaped, and the service is marked FAILED and audited.
- **Evidence:** 6 assertions failed before the fix (each pre-fix run blocked about 30 s).

**C-5: persistent audit corrupted its own chain.**
- **Reachability:** library-only (`audit_persist` is opt-in and off by default).
- **Defect:** lifecycle events advanced the in-memory chain without writing to disk. The
  next persisted record linked to a missing entry, so on the next boot `chain_verify` failed
  and init fell back to in-memory silently and permanently.
- **Fix:** every lifecycle record goes through the persist-aware path.
- **Evidence:** 2 assertions failed before the fix; the store now reopens and verifies.

**C-6: `init_poll_health` allocated on every non-idle tick.**
- **Reachability:** kybernet.
- **Measured:** 232 B per tick with one due probe, plus 152 B per tick for the notify drain's
  pid set.
- **Fix:** module-level vecs, cleared each call. **The returned vec is valid until the next
  call.**
- **Evidence:** 2 assertions failed before the fix; both now measure 0 B beyond the probe's
  own result.

## Considered and dismissed

- **The cryptsetup `--token-only --tries 1` path and `validate_device_path` accepting
  `/dev/shm`:** verity still requires the trusted root hash to match.
- **`break` inside a `while` that declares `var`:** probed correct on 6.7.9. The rule is
  still followed, and the touched files were converted to flags.
- **SCM_RIGHTS fd injection through the notify socket:** the kernel writes credentials
  first, and fds that do not fit set MSG_CTRUNC, which is rejected. **Corrected at
  1.16.2:** this holds only on a socket with `SO_PASSCRED`, which every `notify_bind` socket
  has. On a consumer's socket without it, one `SCM_RIGHTS` header fits the control buffer.
  The descriptors were installed in PID 1 and never closed. That leak is now fixed; see
  the second-to-last row of the table under
  [Fixed at 1.16.2](#fixed-at-1162-previously-deferred).
- **Signalfd read sizes and the child signal mask:** correct. The mask has been reset before
  exec since 1.6.3.
- **The streaming head-hash lifetime:** every in-tree caller discards the return value.
- **`_RSC_ARGV[18]` against argc ≤ 16, and a 4-byte wait status read with `load64`:** both
  in bounds.

## Fixed at 1.16.2 (previously deferred)

The user made the four policy decisions on 2026-10-14:
- the KDF and its format: Argon2id in kybernet's v1 format;
- the emergency-shell default: require authentication, fail closed;
- the health-audit policy: transitions plus an hourly heartbeat;
- the TPM item: document only.

Each fix was written test-first. The new suites failed against the 1.16.1 tree before the
fixes:
- `shutdown_audit`: 40 of 77, plus 2 restart-limit assertions;
- `emergency_kdf`: 63 failures, then a SIGSEGV on a null config;
- `deferred_fixes`: 37 of 103, plus the SCM_RIGHTS leak.

Full detail is in CHANGELOG [1.16.2].

| Item | Severity | Fix |
|---|---|---|
| C-8 `init_stop_all` ignores dependency order | LOW | `init_execute_shutdown` stops in reverse waves, one SIGTERM batch per wave, and the waves share one deadline. Each wave gets the time left ÷ live waves left. A straggler gets a process-group SIGKILL plus up to 500 ms to be reaped. Every member ends STOPPED with pid 0, its proc-table entry removed and an audit record. `init_stop_all` keeps its signature and runs it, so kybernet's existing call is ordered |
| Emergency shell open by default | LOW | `emergency_shell_default()` sets `require_auth = 1` with no credential, so it denies until one is configured. It shipped together with the roadmap KDF item: `verify_emergency_auth` accepts a v1 Argon2id record (kybernet's format and bounds, rejected rather than clamped). It uses a private, unmapped-before-verdict `mmap` arena, so PID 1's bump arena grows by 0 bytes. The legacy SHA-256 path is unchanged byte for byte; a null config or password now denies (it crashed) |
| `WatchdogSec=` under `Type=simple` | LOW | Emitted only for `SVC_NOTIFY`, from `watchdog_ms` |
| ExecStart prefix characters | LOW | `generate_unit` returns 0 unless the binary is an absolute path |
| `notify_try_recv` cannot detect truncation | LOW | It now reads through `recvmsg` and drops `MSG_TRUNC` datagrams. It passes no control buffer, so no descriptor can be installed. It and `notify_drain` are `#deprecated`, with removal planned for 1.17.0 |
| Native `*at` tmpfiles | LOW | `tmpfiles_apply` walks every path from `/` with `openat(O_PATH\|O_DIRECTORY\|O_NOFOLLOW)` and creates entries with `mkdirat` / `symlinkat` / `mknodat`. It sets owner and mode on an `O_NOFOLLOW` fd. An existing symlink is replaced atomically via `renameat`; a file or directory is never replaced. `ag_sys_symlinkat` was added (x86_64 266 / aarch64 36, traced on both) |
| **New:** fds passed to PID 1 without `SO_PASSCRED` | LOW | `notify_try_recv_authenticated` closes every `SCM_RIGHTS` descriptor in the received control data before any verdict. The test sends one fd over a socketpair without `SO_PASSCRED`: PID 1's lowest free fd moved from 9 to 10 before the fix and stays at 9 after |
| **New:** a restart refused at the limit is unaudited | LOW | `EVT_RESTART_LIMIT` ("RestartLimitReached", error severity) is written where `init_restart_service` gives up; before, the chain showed a crash followed by nothing. The enum value is appended, so no existing value shifts |
| One audit record per passing probe | PERF | A health result is recorded when it is the first since a (re)start, when it differs from the last recorded result, or when it is a pass at least `HEALTH_AUDIT_HEARTBEAT_MS` (1 h) after that service's last health record. Failures are not re-recorded; the restart and give-up actions they cause are |
| CVE-2026-32606 class (TPM key release) | unclear | `docs/architecture/005-edge-boot-tpm-key-policy.md`. argonaut has no TPM code, and kybernet reads `pcr_bindings` as a read-out set, not a sealing policy. The note gives the enrolment to use: measure the verified verity root hash into PCR 15 before unlocking, bind the token to PCR 7 + 15, cap PCR 15 afterwards, prefer a signed policy, and keep the emergency shell authenticated |
